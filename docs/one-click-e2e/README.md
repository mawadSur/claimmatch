# One-click official-form dry runs

`scripts/one-click-dry-run.ts` opens each real official claims site, fills a
clearly fake identity (`Testonly Claimmatchdryrun` / `dryrun.not.a.real.claim@example.com`),
walks Next/Continue, and **stops before the final Submit control**. It never
sends a claim. `--submit` is refused.

On Angeion Yes/No gates it clicks **No** (no-notice path) then Continue. Visible
captcha widgets and Claim Form Login (LoginID + secret) stop the walk; page JS
that merely mentions recaptcha is not treated as a captcha.

Screenshots: `docs/one-click-e2e/<slug>/final-step.png`.

The five slugs and owner-apply SQL are generated by
`scripts/one-click-five-settlements.ts` → `supabase/owner-apply/one-click-five-settlements.sql`.
Later candidates: `scripts/one-click-more-settlements.ts` →
`supabase/owner-apply/one-click-more-settlements.sql`. Claim-profile drafts:
`scripts/one-click-claim-profile-settlements.ts` →
`supabase/owner-apply/one-click-claim-profile-settlements.sql` (Rolling Stone
`rolling-stone-magazine-lifetime-subscription`, Hyundai/Kia `hyundai-kia-vehicle-theft`).
Default dry-run walks the additional slugs; `--slug` still works for any listed settlement.

The owner applies that SQL, then a legal_reviewer approves each spec and policy
in Admin → Filing. Do not approve a draft whose dry-run stopped at account-login,
captcha, or a required proof upload. Do not apply the SQL from CI.
